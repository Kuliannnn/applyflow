# ApplyFlow 视觉候选方案 V2

> 历史候选方案，已被用户确认的 [V3 正式设计](../../DESIGN.md)取代；下文仅记录当时思路，不作为当前实施规范。

根据用户对 V1 的反馈：增强实验感、去掉蓝色、简化版面与工作流，不再限定白色。参考 light-ripple_SKILL.md 的光波语言，采用炭黑、骨白与少量暖金色。此方案尚未替换现有前端 skill，也未实现前端。

## 三张原型

- `01-new-application.png`：以粘贴职位描述为入口，保留一个主要操作。光波集中在留白处。
- `02-analysis-focus.png`：优先展示两项准备重点，同时提供原文与依据入口；未填写自评不等于没有技能。
- `03-application-followup.png`：以列表展示申请，展开当前条目即可查看下一步并更新进度。

移除固定侧栏、统计卡片堆叠与多层导航。个人资料和个人 AI API 配置放在账户菜单内；未配置时，在分析入口提供明确的设置入口。原型中的“已连接”仅为演示状态。

## 落地时需要补全的交互

1. 粘贴 JD 后，补齐或确认公司、岗位等必填信息，成功保存申请后才发起分析。原型省略了该过渡状态，不代表当前 API 支持仅提交 JD 创建申请。
2. 分析页的“保存并跟进”在实现时应改为“进入申请”，明确申请已保存，避免重复创建。准备清单需明确保存状态。
3. 进度条只是概览分组，实际更新使用既有状态枚举，并覆盖结束、撤回等分支。
4. 补齐首次使用、空列表、分析中、失败重试、API 未连接及窄屏布局；主要操作始终可定位。
5. 光波不覆盖输入和阅读区域。若实现动态效果，支持减少动态效果偏好，页面不可见时暂停，并提供静态降级。

## 资产

图片由内置 imagegen 生成，为静态视觉参考；细小文字和实际组件尺寸应在代码实现中校正。完整生成提示保存在 `prompts.json`。保留 V1 以便对照。
