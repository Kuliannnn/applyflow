# ApplyFlow V3 — Job to application documents

状态更新：用户已确认此视觉方向。维护中的正式规范见 [DESIGN.md](../../DESIGN.md)，核心架构见 [Application Studio](../../../architecture/application-studio.md)。以下保留原型说明；项目与已安装 skill 均以更新后的 Light Glass Studio 规范为准。

## 用户明确的产品重点

默认英文页面。用户提供职位描述截图、文字或链接，AI 结合用户真实简历与个人资料，生成针对职位的简历和 Cover Letter，允许审阅、修改与导出。申请跟踪是后续辅助流程。

此优先级来自用户本轮明确要求，取代 V1/V2 原型以管理申请和面试准备为中心的安排。旧架构把简历主要视为附件，因此不能将已有 API 当作已支持本流程；原型阶段仅交付视觉参考；后续已更新产品/架构/skill，业务功能与新增契约仍待实现。

## 材质与语言

- 默认界面、状态、错误及表单提示使用英文。文案集中管理，未来可扩展本地化。
- 保留最初 glassmorphism_DESIGN.md 的核心：玻璃自身为中性白色半透明，颜色来自后方模糊背景，辅以细边框、顶部高光和柔和阴影。
- 背景为浅杏桃、柔粉、香槟与浅鼠尾草绿的扩散混光；不使用全黑背景或蓝色主调。
- 深色文字直接落在玻璃表面；长文区增加白色填充确保阅读。主要操作使用深橄榄色实心按钮。
- 图片中的室内物体、边角暗影和标志差异是生成式概念图的细节，不作为组件规范。实现时统一字标和导航，背景采用抽象混色模糊光场，去掉可辨识家具和重暗角。
- 不沿用旧 applyflow-light-glass skill 中与用户新要求冲突的固定侧栏、蓝色按钮和禁止彩色光斑规则。项目 skill 已按确认方向重写，并同步已安装副本。

## 原型与流程

1. `01-job-intake.png`：统一输入区域接受粘贴 JD 文字、职位链接、粘贴/拖入/上传截图。显示所选基础简历，可更换；首次使用显示 Upload resume。主操作 Create my drafts。
2. 输入处理后展示简短确认：公司、岗位、提取出的 JD，可直接修正。截图 OCR 不确定处明确标记；链接无法读取时保留输入并提示粘贴文字或截图。确认后进入生成，避免根据错误提取内容写作。
3. `02-tailored-resume.png`：在 Resume 标签审阅生成版本，查看改动、补充实际经历、与原简历比较，也可用自然语言提出修改。
4. `03-cover-letter.png`：在同一工作区切换 Cover letter，调整语气、长度、个人动机，修改后导出。当前文档仍可直接编辑。
5. 草稿自动保存与“保存到申请记录”须区别明确：后者建立/关联跟踪记录，不是首次持久化内容。失败时保留已输入资料；任何已保存提示必须来自真实成功结果。

## 数据与行为边界

- 基础简历保持不变，每次生成保留独立版本及 JD、简历、资料的输入版本。重新生成不能静默覆盖用户编辑，应提供版本选择或改动审阅。
- 仅重组、强调和润色用户已提供的事实。没有证据的技能、经历、学历和量化成果向用户询问，不根据 JD 补造。两份材料使用一致的事实来源。
- 图片里的人名、公司、简历、状态均为演示内容；默认生成英文材料，材料语言未来可单独配置。
- 账户菜单保留 Profile、My resumes、AI settings。AI 未配置时提供设置入口，回来后保留 JD 和简历选择。
- 生成前说明将所选 JD、简历及相关资料发送到当前 AI 服务商。旧文档“仅发送 JD”规则需要随新工作流正式更新，不能直接沿用。
- 草稿审阅与导出为主要操作，不自动发送求职邮件或提交申请。
